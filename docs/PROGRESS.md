## Known gaps and interim pieces (explicit, per the working rules)

- **Audit anchoring defaults to the file store.** `Quicker:Audit:Anchoring:Store=object_lock` writes retained objects through `IObjectStorage` (S3 object lock in compliance mode with the `s3` provider; the `filesystem` provider only refuses through its own API, so on a single node the file store's hash-linked lines remain the tamper-evident choice). Anchoring and verification now run daily as the platform jobs `audit.anchor_all` (02:00 UTC) and `audit.verify_all` (03:00 UTC; the job fails, and is visible as such, when any chain is broken). Verification and export from the API still run synchronously inside a request (page size 2000, export capped at 50 000 rows).
- **Audit retention** (dropping partitions older than the configured period, default 10 years) is not implemented; nothing deletes audit data yet.
- **Email is SMTP only.** `Quicker:Email:Provider=smtp` sends through any relay (Mailpit locally); the default `capture` keeps messages in memory and logs them. Provider APIs (SES, SendGrid, Postmark), bounce handling and per-tenant sender identities are not implemented; the identity module's invitation and reset emails still go straight to `IEmailSender`, not through the notification log.
- **Attachments are not scanned or authorised per record.** Uploads are limited by size and stored by hash, but there is no malware scan and the `collaboration.attachment.*` permissions are tenant-wide until documents (M2+) carry their own record permissions; objects orphaned by a failed commit after upload are not swept yet.
- **WebAuthn ceremonies are not covered by automated tests.** Registration/assertion options, storage and verification are implemented with Fido2NetLib, but no test generates a real authenticator attestation; a browser check is scheduled with the web shell in 1.10.
- **Paging and filtering are applied where lists are unbounded** (notifications, activities, webhook deliveries, audit events) and the filter language to companies; other lists (companies, branches, roles, series, jobs, schedules) return whole arrays until they can grow, and each new list endpoint adopts `Page<T>` and a `FilterSpec` as it lands. `or` is not in the filter language (use `in`). Version ETags with `If-Match` are on companies; other resources have body-hash ETags (304 only) until they expose `updatedAt`.
- **The Iraq statutory chart is group level and provisional** (nine groups of the Unified Accounting System; ASSUMPTIONS Q9): the mapping mechanism, the seeded reference table and the template mapping are complete, the detailed statutory codes below the groups are added once an Iraqi accountant validates them. Statutory reports themselves belong to M2.5/M6.
- **Chart admin UI is pending the M2 web pass (2.5)**: charts, accounts, dimension rules and mappings are configured through the API and CSV import/export until then.
- **Account changes are not yet guarded by postings** (type, chart or header changes on an account that already has journal lines): the guard arrives with the posting engine in 2.2, which is the first slice that writes lines.
- **The demo tenant is purged physically on reseed**, audit chain included, through the owner connection in maintenance mode; that path exists only for the `demo` slug and the seeder, and no API or job deletes a tenant (tenant offboarding with retention is a later platform slice). Demo passwords are shared and printed by the command; a deployment that exposes the demo publicly should reseed it on a schedule.
- **Demo seed v1 stops at the organisation layer** (companies, branches, users, roles, rates) as the roadmap says; items, partners and documents arrive with the seed versions of M3–M6. Company and branch ids are assigned by the services, so they change on reseed while tenant, user and membership ids stay fixed.
- **The API contract may still break before the first release tag**: the gate compares against `main`, and this branch's own history shows one intentional break (three lists became page envelopes). From the first tagged release on, A-082 applies without exception.
- **60 operations have no response schema in the contract** (anonymous objects such as `{count}`, multi-branch lambdas, streams and files); they are valid but untyped for the client until each is given a DTO and a typed result. The contract is one document for the whole API, not per tenant: custom fields are described by `GET /collaboration/custom-fields/{entityType}/schema`.
- **Logs reach the collector through stdout, not OTLP**: Serilog writes JSON to the console for the platform's log shipper (Loki in the local profile reads container output); the OTLP log signal is not wired (`Serilog.Sinks.OpenTelemetry` when a deployment needs it). Runtime and process metrics (GC, thread pool) are not exported yet; log levels are set at start, not adjustable at runtime; the per-tenant "system health" admin page (ADR-0025) reads the same gauges but is not built yet.
- **Rate limits are in-process per node** (sliding windows in memory): a multi-node deployment multiplies the budget by the node count until a shared store (Redis) backs the limiter (1.11 hardening).
- **Custom fields have one host today** (`company`). Each document module registers its table when it lands (M2 onwards); the OpenAPI document is not rewritten per tenant, clients read `GET /collaboration/custom-fields/{entityType}/schema` instead. Index DDL runs without `CONCURRENTLY` (fine while tables are small; the online variant is a follow-up before large tenants).
- **Comments, links and views are tenant-wide**: a member who can read comments reads them on any record; per-record authorisation follows the document permissions of M2+.
- **Central Bank of Iraq rate adapter is not implemented.** The roadmap lists ECB, Open Exchange Rates and a CBI adapter; the first two ship (parsers covered by tests, import covered end to end against a local stub). The CBI page has no stable machine-readable feed I could verify from this environment, so the adapter is deferred rather than shipped untested; Iraq's official and market rates are entered manually or through a rate type an integration fills. Neither live feed has been called from this environment (no egress); the first production import should be watched.
- **Scheduled rate import** is available as the tenant job `organization.rates.import` (`PUT /api/v1/platform/schedules {code, jobType, cron, payload:{provider, rateType}}`); no tenant has one by default.
- **Fiscal year closing** (`status = closed`, closing entry, reopening a year) belongs to the Closing module (ADR-0026 year-end); today years are `future` or `open`, and period states are the only lock.
- **Company `chart_id` and `posting_profile_id`** are plain nullable columns until Accounting (M2) creates the tables they reference.
- **Numbering has no shipped series.** Series are admin data created through the API; each document module (M2 onwards) registers the default series its document types need when it arrives, so a fresh tenant has no series until then. Document types are free codes until the document registry exists.
- **Numbering roles.** No shipped role template grants `numbering.*` yet; the owner/admin wildcard covers it. Role templates gain numbering grants with the accounting roles in M2. The same holds for `platform.*` (jobs and schedules).
- **Outbox archive is a delete.** Published messages and their inbox rows older than 30 days are deleted by `ops.outbox_archive`; the archive partition of ADR-0010 arrives when reporting needs event history.
- **A dead letter blocks its aggregate.** Later events of the same aggregate wait until an operator retries the dead one (strict per-aggregate order); there is no "discard" action yet.
- **Embedded worker is off by default** (`Quicker:Worker:Embedded=false`); `make up` runs the separate `worker` service. The worker image is not built in CI (only the solution is built and tested there).
- **Job progress is polled**, not pushed: the server-sent events channel for progress arrives with the web shell (1.10).
- **Idempotency-Key is optional** until the web client (1.10) and the generated TypeScript client (1.9) send it on every mutation; then `Quicker:Api:Idempotency:Required=true` becomes the default. Responses above 1 MB are not stored (a replay re-executes).
- **Webhook filters are stored, not applied** (`filters` on a subscription); filtering by company or document type arrives when documents carry those attributes (M2). The event catalogue section of the OpenAPI document (AsyncAPI-style) is part of 1.9.
- **Webhook receivers are not IP-restricted** and private-network URLs are not blocked yet (SSRF guard: an allow/deny list per deployment is part of 1.11 hardening).
- **The web shell covers the admin screens of 1.4–1.8 at v1 depth**: branches, fiscal and business calendars, dimensions, units, company settings, numbering series, SoD rules, API keys, SSO connections, comments/attachments on records and the audit event detail are API-only until their screens land with the modules that use them (M2+). Forms are controlled React state, not TanStack Form yet; the grid has no inline editing, grouping, pinning or export yet (data grid v2 with the first document lists). The company form sends the posting policies it does not show (defaults on create, unchanged on edit) because the contract marks them required. The 100k-row grid performance budget is met by virtualization but not yet measured in CI.
- **The mobile web scanning app** (PWA, camera, offline queue) is not started; the shell is responsive (sidebar drawer under 1024px) and touch targets are 44px.
